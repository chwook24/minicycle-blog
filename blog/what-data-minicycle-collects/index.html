What data MiniCycle collects, and what stays on your phone

Published June 18, 2026·by Chanwook Kim, MiniCycle developer·Updated September 2, 2026·3 min read

At a glance

MiniCycle handles app records and analytics as different data flows. Period dates, notes, sexual-activity markers, and settings are stored on the iPhone by default, with an optional CloudKit copy when iCloud Sync is enabled. Separately, Firebase Analytics sends product-interaction and SDK-generated analytics data. MiniCycle's custom events are designed not to contain cycle dates or note text, but that statement should not be mistaken for a claim that the SDK sends nothing else.

App records

Period dates, daily notes, sexual-activity markers, and cycle and app settings are stored on the device by default. MiniCycle does not require a MiniCycle account and does not operate its own server that stores your cycle history.

If you enable iCloud Sync, the app stores a copy in the CloudKit private database associated with your Apple ID. That copy supports restoration on another iPhone after you enable iCloud Sync there as well.

Firebase Analytics

The app includes Google's Firebase Analytics SDK. MiniCycle defines events for app opens, screens and tabs, calendar interaction, generic core actions, widget configuration and opens, general settings, notification permission, onboarding, and iCloud Sync status. Firebase can also collect automatically generated events, an app-instance identifier, and technical metadata described in Google's documentation.

App Store privacy details should disclose product-interaction data used for analytics. MiniCycle does not use this data for tracking, but Firebase remains a third-party analytics SDK and this is not a promise that no data leaves the device.

What MiniCycle's custom events omit

MiniCycle's custom event parameters are designed not to include period dates, memo text, sexual-activity markers, record types, record-entry locations, health-related validation reasons, exact cycle settings, exact notification times, or cycle history. The generic core-action event only distinguishes created, updated, deleted, or cleared actions and whether the action succeeded or was blocked.

This description covers MiniCycle's event design. For the SDK's automatically collected events and metadata, Google's current Firebase documentation is the authoritative source.

Website analytics

The MiniCycle website separately uses Google Analytics for page measurement. Website page views and in-app record events are sent as separate data streams. The website does not read the period dates, notes, or cycle history stored by the app.

Limits of local storage

Local-by-default storage reduces the need for a MiniCycle account or cycle-history server, but it is not a complete privacy guarantee. Device backups, optional iCloud Sync, screenshots, shared devices, and access to an unlocked phone still matter.

For the current formal description, read the MiniCycle privacy policy and the App Store privacy details. Firebase is a third-party SDK governed by Google's terms and documentation.
